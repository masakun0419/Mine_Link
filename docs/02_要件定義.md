# 02 要件定義

## 1. 機能要件

| ID | 機能 | 概要 | 優先度 |
|---|---|---|---|
| F-001 | ルーム作成 | ホストがMinecraft Serverを公開する | 必須 |
| F-002 | 参加コード発行 | 推測されにくい参加コードを発行する | 必須 |
| F-003 | ルーム参加 | ゲストが参加コードで接続する | 必須 |
| F-004 | TCP転送 | Minecraft Java版のTCP通信を中継する | 必須 |
| F-005 | ローカル待受 | ゲストPCの`127.0.0.1`で接続を受け付ける | 必須 |
| F-006 | 接続者表示 | ホストが参加者名と状態を確認する | 必須 |
| F-007 | 切断 | ホストが指定ユーザーを切断する | 必須 |
| F-008 | 状態表示 | 接続状態、Ping、転送量を表示する | 必須 |
| F-009 | 設定保存 | ポート、表示名、テーマ等を保存する | 必須 |
| F-010 | ログ表示 | アプリ内で利用者向けログを表示する | 必須 |
| F-011 | Minecraft起動 | Minecraft Launcherを起動する | 任意 |
| F-012 | 自動更新 | 新版を検出し、安全に更新する | 将来 |
| F-013 | UDP転送 | Minecraft統合版の通信を中継する | 将来 |

## 2. 主要ユースケース

### 2.1 ホストが公開する

1. ホストがMineLinkを起動する。
2. Minecraft Serverの接続先を確認する。
3. 「サーバーを公開」を押す。
4. MineLinkがローカルサーバーへの疎通を確認する。
5. Relayへ接続し、ルームを作成する。
6. 参加コードを画面へ表示する。
7. ゲスト接続後、接続者一覧を更新する。

### 2.2 ゲストが参加する

1. ゲストが参加コードと表示名を入力する。
2. MineLinkがRelayへ接続する。
3. 参加が許可されたらローカル待受ポートを開く。
4. 接続先`localhost:ポート番号`を表示する。
5. Minecraftからローカル待受ポートへ接続する。
6. Minecraft通信をRelay経由でホストへ転送する。

## 3. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| NF-001 | 操作性 | 初回利用者が3操作以内で公開または参加を開始できる |
| NF-002 | 性能 | Relay追加遅延は良好な回線で目標30ms以下とする |
| NF-003 | 可用性 | Relay切断時に自動再接続を最大3回試行する |
| NF-004 | セキュリティ | インターネット区間をTLS 1.3で暗号化する |
| NF-005 | 保守性 | GUI、通信コア、APIモデルを別プロジェクトに分離する |
| NF-006 | 互換性 | Windows 10 22H2以降、Windows 11を対象とする |
| NF-007 | 配布 | x64自己完結型パッケージを提供する |
| NF-008 | ログ | 秘密情報やMinecraftデータ本文をログへ保存しない |
| NF-009 | 復旧 | 異常終了後も次回起動でき、使用中ポートを検出できる |

## 4. 制約

- VPSを経由するため、遅延と転送費用が発生する。
- VPS障害中は新規接続および既存通信を継続できない。
- セキュリティソフトがローカル待受や外向き通信を遮断する可能性がある。
- Minecraft Server自体の設定や不具合はMineLinkの保証対象外とする。
